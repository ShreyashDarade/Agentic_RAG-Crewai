| LLM providers | `crewai.llm.LLM`; native SDK routing for `openai, anthropic/claude, azure, google/gemini, bedrock/aws`, OpenAI-compatible `openrouter, deepseek, ollama, ollama_chat, hosted_vllm, cerebras, dashscope` (`SUPPORTED_NATIVE_PROVIDERS`); anything else falls back to LiteLLM | `chat_model` registry: `openai` (direct SDK) and `crewai` (any provider string). Crew agents, manager LLM and judge LLM each take a provider setting | Cloud providers cannot be verified without credentials; the provider matrix in `docs/providers.md` records `verified / unverified` per provider |
| Embedding providers | `crewai.rag.embeddings` `AllowedEmbeddingProviders`: `azure, amazon-bedrock, cohere, custom, google-generativeai, google-vertex, huggingface, instructor, jina, ollama, onnx, openai, openclip, roboflow, sentence-transformer, text2vec, voyageai, watsonx`; `build_embedder(spec)`; `custom` accepts a callable | `embedder` registry adapter `crewai` (provider chosen by settings) next to the direct `openai` adapter; an embedding **dimension and model id are recorded in collection metadata** and a mismatch is a typed error (CrewAI itself only warns about dimension mismatch: `knowledge_storage.py`) | `openclip`/`roboflow` are image-embedding providers: only useful once image chunks are embedded as images (not planned) |
| Vector DB clients | `crewai.rag` `BaseClient` protocol; native clients for **ChromaDB** and **Qdrant** only (`RagConfigType = ChromaDBConfig \| QdrantConfig`); **no Milvus** | `vector_store` adapters: `milvus` (ours, pymilvus), plus `crewai` Chroma and Qdrant clients registered under the same port and the same conformance suite. Milvus is plugged into CrewAI by implementing its pluggable storage seams (next two rows), not by `set_rag_config` (which only accepts Chroma/Qdrant configs) | |
| Knowledge | `crewai.knowledge.Knowledge`; sources `StringKnowledgeSource, TextFileKnowledgeSource, PDFKnowledgeSource, CSVKnowledgeSource, ExcelKnowledgeSource, JSONKnowledgeSource, CrewDoclingSource`; `BaseKnowledgeStorage` is pluggable (`Agent.knowledge_storage`) | `adapters.crewai.knowledge`: a Milvus-backed `BaseKnowledgeStorage`; agents get `knowledge_sources`/`knowledge` from the same indexed collection. Docling source (layout-aware, hierarchical chunker) registered as a `parser`+`chunker` pair behind the `docling` extra | CrewAI's built-in knowledge chunking is a fixed character window (`chunk_size=4000`, `chunk_overlap=200`, `base_knowledge_source.py`): kept as one registered chunker, not assumed good; the evaluation decides |
| Memory | `crewai.memory.unified_memory.Memory` (scopes, recall and encoding flows, LLM-analysed), default LanceDB storage, `QdrantEdge` storage, pluggable `StorageBackend` protocol (`save/search/delete/update/get_record/list_records/…`); `Crew(memory=...)` accepts `bool \| Memory \| MemoryScope \| MemorySlice` | `adapters.crewai.memory`: a Milvus `StorageBackend`; replaces the current whole-file JSON memory store. Conversation turns are not idempotent appends, so the SDK never auto-retries them (framework §8) | Memory content is derived from user text: size/retention limits and delete-by-scope are required (security §11) |
| crewai-tools RAG loaders / chunkers | `crewai_tools.rag` loaders: CSV, directory, docs-site, DOCX, GitHub, JSON, MDX, MySQL, PDF, Postgres, text, webpage, XML, YouTube channel/video; chunkers: default, structured, text, web; `embedding_service` | `parser` and `chunker` registry entries; file-type loaders enabled by default, **network and database loaders (docs-site, webpage, GitHub, YouTube, MySQL, Postgres) disabled by default** and allow-listed in settings (OWASP API7 SSRF, API8) | Not enabling arbitrary-URL or DB ingestion by default; *needs verification* that each loader works offline in tests |
| crewai-tools search/DB tools | `PDFSearchTool, DOCXSearchTool, CSVSearchTool, JSONSearchTool, TXTSearchTool, XMLSearchTool, MDXSearchTool, DirectorySearchTool, CodeDocsSearchTool, WebsiteSearchTool, GithubSearchTool, YoutubeVideoSearchTool, YoutubeChannelSearchTool, QdrantVectorSearchTool, WeaviateVectorSearchTool, MongoDBVectorSearchTool, CouchbaseTool, SingleStoreSearchTool, SnowflakeSearchTool, DatabricksQueryTool, MySQLSearchTool`; web search (`Serper, Tavily, Brave`), scrape tools, `OCRTool` | `tool` extension point. The crew's default toolset is **one read-only retrieval tool over the `VectorSearcher` port**; the others are individually registered, off by default, and each must pass a "read-only, bounded, allow-listed" tool conformance check before it can be enabled | Write-capable or arbitrary-egress tools are never default (OWASP LLM06 Excessive Agency). Weaviate/Mongo/Couchbase/SingleStore/Snowflake/Databricks adapters need their services: unverifiable here, registered as *unverified* |
| Crew orchestration | `Crew(process=Process.hierarchical, manager_llm, manager_agent, planning, memory, knowledge_sources, embedder)`, `Agent(guardrail, max_iter, knowledge_storage, embedder)`, `Task`, `max_rpm`, response caching, event bus (`crewai.events`) | `adapters.crewai.pipeline` uses sequential and hierarchical processes (both evaluated), guardrails to enforce the citation/grounding contract, `max_iter`/`max_rpm` as mandatory budgets, event bus → request-scoped metrics and traces | |
| Flows | `crewai.flow` | Candidate for ingestion orchestration; *evaluate* against a plain job queue at Step 16 | Not adopted by default |
| Out of scope for "RAG parts" | A2A, MCP client, skills, project scaffolding CLI, hooks | Not used | Stated so "100%" is bounded: these are not retrieval/embedding/chunking/storage features |
| Telemetry | CrewAI sends anonymous usage telemetry unless `OTEL_SDK_DISABLED`, `CREWAI_DISABLE_TELEMETRY` or `CREWAI_DISABLE_TRACKING` is `true` (`telemetry/telemetry.py`) | The container sets `CREWAI_DISABLE_TELEMETRY=true` before importing CrewAI; test asserts it | |
